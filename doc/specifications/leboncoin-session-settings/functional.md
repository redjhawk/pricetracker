# Functional specification: LeBoncoin session settings

Status: ready (Q-SET-1 resolved by the user on 2026-10-03: “Warn and reload”)\
Owner: functional specification agent\
User decision/reference: user request and decisions 1–6 of 2026-10-03, quoted in the [change index](../../changes/2026-10-03-1741-leboncoin-session-settings/index.md). Readiness does not imply approval of any API contract.

## Purpose and scope

Let the operator view, set, replace, and clear the LeBoncoin verification session from the application interface, so that the application stores the session itself and no session file, environment variable, or server shell access is needed. The actor is the operator using the shared, no-login interface; any person who can open the interface can use and read these settings.

Included: the **Settings** modal opened from the [header menu](../app-header-menu/functional.md); its single form entry **LeBonCoin session**; input normalization and validation; saving and clearing; durable server-side storage; display of the current saved value, including values renewed automatically by the collector; and a hint showing that the last LeBoncoin attempt using the session failed.

Excluded: other settings; accounts, login or masking of the value; a separate Clear button; automatic challenge solving; triggering a price check when saving; how the collector uses the session (specified in [session collection](../leboncoin-session-collection/functional.md)); the desktop helper (specified in [session capture](../leboncoin-session-capture/functional.md)).

Terms: the **session value** is the value of LeBoncoin's `datadome` cookie. A **session-assisted attempt** is a LeBoncoin collection attempt that sent the saved session value.

## States and corner cases

- **Modal states:** loading; load failed (save unavailable); loaded with no session; loaded with a session; loaded with a rejection/failure hint; loaded with expired/revoked status; saving; save failed; validation error; changed-since-opened (reload required, FR-LBC-SET-017).
- **Long values:** real `datadome` values are long; the entry must let the operator see and select the entire value.
- **Pasting with surrounding whitespace or line breaks:** trimmed (FR-LBC-SET-005); internal whitespace inside the value is invalid (FR-LBC-SET-006).
- **Duplicate identical `datadome` pairs** in a cookie string are accepted as one value; different values are rejected.
- **Saving an unchanged value again** (with no concurrent change) is a normal save per FR-LBC-SET-007; a concurrent change is handled by FR-LBC-SET-017.
- **Stale modal:** a save conflicting with a change made after the modal loaded is refused with a reload request (FR-LBC-SET-017); the operator's input is kept so it can be copied after reloading.
- **Shared application:** without accounts, the setting is global; a change by one operator affects all collection and is visible to every viewer.
- **Server unreachable:** handled by FR-LBC-SET-003 and FR-LBC-SET-010; nothing is cleared.
- Existing item list, details, refresh, add and delete behaviors are unchanged.

## Open questions

None. Q-SET-1 was resolved by the user on 2026-10-03: “Warn and reload” — if the saved session changed after the modal was opened (auto-renewal, or a save from another browser), Save must detect it, change nothing, and ask the operator to reload the modal before saving (FR-LBC-SET-017).
