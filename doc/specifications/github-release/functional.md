# Functional specification: GitHub release

Status: ready
Owner: functional specification agent
User decision/reference: user request "a script to create a GitHub release" (2026-11-08), with confirmed answers: amd64 binary only (built by `scripts/build-release.sh amd64`); automatic date tag `vYYYY.MM.DD-N` (UTC, N from 1, incremented if the day's tag exists locally or on origin); GitHub-generated release notes; `install-pricefollower.sh` not attached.

## Purpose and scope

A maintainer runs one script from a clone of the repository to publish a GitHub release of the current commit containing the Linux x86-64 (amd64) `pricefollower` binary with the frontend embedded.

Actor: maintainer with push rights on the repository and an authenticated GitHub CLI session.

Included: build of the amd64 binary, automatic version tag, tag push, release creation with generated notes, binary attachment.

Excluded: ARMv6/ARMv7 binaries, `install-pricefollower.sh` or any other asset, hand-written release notes, version input by the maintainer, deployment of the release, CI automation. No application (web or API) behavior changes.

## Requirements

| ID | Trigger / precondition | Required behavior | Observable acceptance criteria |
| --- | --- | --- | --- |
| FR-GHREL-01 | Maintainer runs the release script | The script builds the Linux amd64 binary with the frontend embedded, reusing the existing release build. | Given a clean clone, when the script runs, then the amd64 build runs and the binary is produced before any tag or release is created. |
| FR-GHREL-02 | Build succeeded | The version tag is `vYYYY.MM.DD-N`, where the date is the current UTC date and N is the smallest integer from 1 for which no tag with that name exists locally or on origin. | Given no tag for today, then the tag is `vYYYY.MM.DD-1`; given `vYYYY.MM.DD-1` exists locally or only on origin, then the tag is `vYYYY.MM.DD-2`. |
| FR-GHREL-03 | Tag chosen | The tag points to the current commit (HEAD) and is published to origin. | After a run, `git ls-remote --tags origin` lists the tag at the HEAD commit. |
| FR-GHREL-04 | Tag published | A GitHub release named after the tag is created for it, with release notes generated by GitHub. | The GitHub release page shows the tag and generated notes. |
| FR-GHREL-05 | Release created | The only attached asset is the amd64 binary, under a name identifying platform and architecture. | The release lists exactly one asset, `pricefollower-linux-amd64`; `install-pricefollower.sh` is absent. |
| FR-GHREL-06 | Release completes | The script reports the tag and the release URL. | Final output shows the tag and a github.com release URL. |
| FR-GHREL-07 | Any precondition or step fails | The script stops with a clear error message and a non-zero exit status, and does not create a release from an unclean or failed state. | See corner cases. |

## States and corner cases

- Required tool missing (go, npm, gh, git): error naming the tool; nothing built, tagged, or released.
- Uncommitted or untracked changes in the working tree: refusal before building, so the release always matches a commit.
- gh not authenticated or origin unreachable: error before any tag is created.
- Build failure: error; no tag, no release.
- Several releases on the same UTC day: each gets the next N (FR-GHREL-02).
- Tag push or release creation failure after the tag was created: error naming the step and the tag, so the maintainer can clean up or retry.

## Open questions

None blocking. Interpretation recorded (from "create a GitHub release"): the release is published (not draft, not prerelease) and its title is the tag.
