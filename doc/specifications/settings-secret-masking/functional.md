# Functional specification: masked secrets in Settings

Status: ready (issue #265)
Owner: functional specification agent
User decision/reference: GitHub issue #265 ("Settings: stop returning the saved Claude token and LeBoncoin session in full").

## Purpose and scope

Today Settings shows the saved Claude token and LeBoncoin session in full, and the server sends both values back whenever Settings is loaded or saved. The user asks that a saved secret never leave the server again. Settings shows instead whether each secret is saved and a short masked hint (the last 4 characters, the issue's suggestion), with an empty input to replace it. Saving must never change a secret the operator did not replace, and removing a secret becomes an explicit action.

Actor: the operator (a logged-in regular user in protected mode, anyone in open mode), using the **Settings** modal from the [header menu](../app-header-menu/functional.md). Each user still sees and changes only their own secrets ([FR-SETTINGS-001](../multi-user-login/functional.md)).

Included: what Settings shows for each secret; replacing, keeping and removing each secret on Save; the LeBoncoin "session changed" check; help texts and the operator guide.

Excluded, unchanged: how a new LeBoncoin session is pasted, normalized and validated (FR-LBC-SET-005/006); Claude token validation and verification (FR-CLT-SET-004/011); the warnings about a rejected, failed, expired or revoked session (FR-LBC-SET-014/015) and a rejected Claude token (FR-CLT-SET-009); one Save applying both entries, all or nothing (FR-CLT-SET-006); loading, saving, cancel and accessibility rules of the modal (FR-LBC-SET-002/003/009/010/011/019, FR-CLT-SET-002/010); how collection and AI reviews use the secrets. No way is added to read a saved secret back in full.

Terms: a **secret** is the saved Claude token or the saved LeBoncoin session value. Its **hint** is the text telling that it is saved and showing at most its last 4 characters. An entry is **untouched** on Save when its input is empty (or whitespace only) and its removal was not requested.

This specification supersedes the parts of [LeBoncoin session settings](../leboncoin-session-settings/functional.md) and [Claude token settings](../claude-token-settings/functional.md) that show the full value, remove a secret by saving an empty entry, or check the LeBoncoin session when it is not being changed; those rows are marked there.

Given saved S, choosing "Remove session", undoing it and saving with an empty input leaves S unchanged. Choosing a removal then Cancel leaves the secret saved. With no saved session, the LeBoncoin entry has no remove action. |

| FR-SECRET-008 | The operator replaces or removes the LeBoncoin session, and the stored session changed after the modal loaded (FR-LBC-SET-017). | Refuse the save as today: nothing is saved (neither entry), the operator's input and requested removal are kept, and the modal asks to reload before saving. When the LeBoncoin entry is untouched, a change of the stored session since loading does not refuse the save and the session keeps its changed state (FR-SECRET-004). | Given modal A loaded with session X and S was then renewed to Y: replacing or removing the session from A is refused with the "session changed" warning and the stored session stays Y; saving only a new Claude token from A succeeds and the session stays Y. After reopening, the hint shows Y's last characters and replacing or removing succeeds. |
| FR-SECRET-009 | The saved session was renewed, expired or revoked (FR-LBC-COL-014/015), or a secret was changed from another browser. | Reopening Settings shows the hint and state of the currently stored secret. Advice texts that told the operator to save an empty entry tell them to remove the session instead. | After a renewal, reopening shows the hint of the renewed value. Given an expired or revoked session, the warning advises capturing a new session or removing it, and the hint of the stored value (if one remains) is shown. |
| FR-SECRET-010 | A secret was saved before this change. | It is kept and shown masked; the operator does not need to save it again. | After the update, Settings shows the hint of each previously saved secret, and LeBoncoin checks and AI reviews keep using it. |
| FR-SECRET-011 | The browser, after the modal closes. | Apart from what the operator types into an input before saving, the browser never holds a full secret; typed input is discarded when the modal closes. | After saving or cancelling, browser storage and the page contain no full secret; reopening Settings shows empty inputs. |

At about 400 px the hints and actions are usable without horizontal page scrolling. |

## States and corner cases

- Per entry: no secret saved (no remove action); secret saved (hint, remove action); removal requested (stated in text, input unusable, undo available); new value typed.
- Load failure: no hint, input, remove action or Save is usable, as today (FR-LBC-SET-003, FR-CLT-SET-002).
- Save failure, validation error, Claude refusal or "session changed": nothing is saved; typed input and a requested removal are kept so the operator can retry or copy the input.
- Replacing one secret and removing the other in one Save is allowed; an error in either saves neither (FR-CLT-SET-006).
- The operator cannot check whether a new input equals the saved secret other than by the last characters of the hint.
- The administrator has no Settings and is not affected.
