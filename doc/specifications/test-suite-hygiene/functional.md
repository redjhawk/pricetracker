## Terms

- **No-download check:** the test helper `AssertNoDownload`, which looks through given folders (the Amazon browser profile, the home folder of the account running the browser) after the browser has closed and fails the test when a file left by a download remains.
- **Content rule:** the part of the no-download check that reads a file to see whether it holds the downloaded body (`DownloadMarker`). It applies to a regular file whose name does not already identify it as a download.
- **Test helper package:** the Go package `pricefollower.local/internal/amazon/amazontest`, which holds the no-download check.
- **Server dependencies:** the Go packages that a program under `cmd/` is built from, directly or indirectly, as the Go tool reports them for a normal (non-test) build. Test files (`_test.go`) are not part of them.
- **Dependency check:** the repository check of issue #244 that fails when the test helper package is one of the server dependencies.
- **Fixture module:** a small temporary Go module, with its own stub of the test helper package, that the unit tests of the dependency check build to run the check on a known set of imports.
- **Follow-up record:** a file under `doc/todo/` that records a non-blocking review comment and the GitHub issue opened for it.
- **Morning window, evening window, scheduled check, failure:** as defined in [Amazon human-like checks](../amazon-human-checks/functional.md) (06:00–09:00 and 19:00–23:00 in the schedule timezone).
- **Due while running:** a scheduled check of an Amazon item whose due time is a past time of the current window when the scheduled checks run, while a check of the same item (Refresh price or first check after add) is still in progress.
- **Upgrade redraw mark:** the mark the database records at the first start after the issue #168 change when Amazon items still hold the check time written before that change (`amazon_request_state.human_checks_redraw = 1`); it asks the application to draw a window time for every Amazon item at its start.
- **Issue #168 test case document:** `doc/changes/2026-11-20-1634-issue-168-error-amazon-checks-were-stopped-on-20-n/testcases.md`, the test cases written for issue #168, including TC-004 (browser results match the current parsing results) and TC-006 (non-success response and challenge page are failures).
- **Accepted image request:** a browser request, made during TC-010 of `tests/platform-tabs.spec.ts`, for the Amazon image URL that TC-010 gives its item with an image (`https://m.media-amazon.com/images/I/price-found.jpg`).
- **Fixture sanity check (TC-002):** the step of TC-002 that starts the browser executable directly (without the collector) on the profile prepared with a lock naming another host, waits for it to open the price-found product page or to end, then stops it (`assertBrowserRefusesProfile` in `internal/amazon/browser_profile_test.go`).
- **Browser output:** what the browser started by the fixture sanity check writes to its standard output and standard error.
- **Lock refusal message:** the message Chromium writes when it refuses a profile because the profile appears to be in use by a Chromium process on another computer (it names the other computer).
- **Fixture check test (issue #195):** the test `TestBrowserProfile_Issue195_FixtureCheckNeedsTheLockRefusal`, whose rows each start a stub in place of the browser on the locked profile, let it run until it exits or the row's wait has passed, stop it, and check what the fixture sanity check reports.
- **Row's wait:** how long a row of the fixture check test lets its stub run before stopping it, counted from the stub's start for a non-hold row and, from issue #315, from the output signal for a hold row; a stub that exits earlier ends the row's run at once.
- **Output signal (issue #315):** the sign, given by a hold row's stub, that it has finished writing its output (possibly empty) and has made its page request if it makes one; the stub keeps running after it.
- **Signal bound (issue #315):** the longest time, counted from the stub's start, that a hold row waits for the output signal: 15 s.
- **Hold row, non-hold row:** a row of the fixture check test whose stub keeps running after writing its output until it is stopped (`Hold`), and a row whose stub exits by itself.
- **Temporary profile (issue #324):** the `pricefollower-browser-*` directory that the collector creates directly under the system temporary folder (`os.TempDir()`) when no profile folder is configured; the subtest "TC-003 temporary profile" receives its path from `profileOf("")`.
- **Collector's cleanup (issue #324):** the cleanup function that `profileOf("")` returns with the temporary profile, and that the subtest calls and checks.
- **1025-space token test (issue #290):** the e2e test "long whitespace TC-005 a 1025-space token input sends no replacement, shows no message and closes" in `tests/claude-token-settings.spec.ts`, which fills the Claude token input of the Settings modal with 1025 spaces, saves, and checks the outcome.
