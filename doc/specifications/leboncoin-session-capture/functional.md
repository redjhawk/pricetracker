# Functional specification: LeBoncoin session capture

Status: ready (revision 2, 2026-10-03; FR-LBC-CAP-010 to FR-LBC-CAP-018 added; file export and Raspberry Pi transfer superseded)\
Owner: functional specification agent\
User decision/reference (revision 1): The user answered “Yes, manual verification is acceptable” to completing the verification in a browser on their computer, securely transferring the verified session to the PriceFollower Raspberry Pi, and repeating this when rejected. This approval covers that workflow; it does not approve an HTTP contract change.\
User decision/reference (revision 2): user decisions 6 and 7 of 2026-10-03 for change [leboncoin-session-settings](../../changes/leboncoin-session-settings/index.md): keep the desktop helper that opens a browser, but print the captured `datadome=...` string in the terminal for pasting into the Settings modal instead of writing a file; fix the report that the helper “doesn't open a browser” and prints no message.

## Revision 2 summary

The helper no longer writes a session file and there is no transfer/installation on the server. After verification it prints a `datadome=<value>` string that the operator pastes into **Settings › LeBonCoin session** ([settings subject](../leboncoin-session-settings/functional.md)). Printing the value in the operator's own terminal is an explicit user decision that supersedes the revision 1 rule that cookie values never appear in terminal output. Revision 2 also requires that a visible browser window reliably opens and that the operator always sees progress and clear failure messages. FR-LBC-CAP-002, FR-LBC-CAP-003 and FR-LBC-CAP-004 remain in force (in FR-LBC-CAP-004, “export” now means printing per FR-LBC-CAP-011). Superseded rows below are kept for history; see the [deprecation record](../../deprecated/leboncoin-session-file.md).

## Purpose and scope (revision 1, history)

Let the operator establish a verified LeBoncoin session on their desktop computer and transfer the session material needed by the existing Go collector to the Raspberry Pi. The operator performs any interactive verification. A command-line helper and documented secure transfer/install steps implement the coordinator's selected workflow; there is no new application screen or HTTP endpoint.

The actors are the operator, the desktop helper, LeBoncoin, and the operator's existing Raspberry Pi deployment. Prerequisites are a supported visible desktop browser, access to a supported LeBoncoin listing, and the operator's existing permission to install the exported file on their server. Browser dependencies and commands belong in the technical specification and operator documentation.

Excluded: account login, personal browser profile access, account-cookie export, automated CAPTCHA solving, paid services, proxies, a mandatory browser process on the Raspberry Pi, or guarantees that a desktop session will be accepted from a different device/network.

## States and corner cases (revision 1, history)

Capture states are validating input, opening the browser, waiting for human verification/listing access, exporting, and completed or failed. Text feedback must distinguish these states without revealing the cookie; no new Carbon interface is introduced. The helper's own commands and cancellation must be keyboard usable. Accessibility of LeBoncoin's third-party challenge is outside this application's control.

A listing that is removed or otherwise cannot be verified as the requested loaded listing does not establish capture success. The operator can choose another supported listing. A successful capture does not itself add an item, collect a backend price, or prove that the Raspberry Pi will be accepted. The existing tracked-item workflows remain the means to observe server-side results.

## Purpose and scope (revision 2)

Let the operator obtain a verified LeBoncoin `datadome` session on a desktop computer with a graphical session, using a dedicated visible browser in which the operator completes any LeBoncoin verification personally, and display the resulting `datadome=<value>` string in the terminal so the operator can paste it into the application's settings modal from any device.

Actors: the operator, the desktop helper, the desktop browser, and LeBoncoin. Prerequisites: a desktop with a graphical display, a supported Chrome/Chromium browser, the runtime and repository dependencies documented for the helper, and an active supported LeBoncoin France listing. Excluded: writing any session file, transferring files to the server, account login, use of the personal browser profile, automatic challenge solving, paid services, proxies, and guarantees that the session will be accepted from the server's device or network.

| FR-LBC-CAP-013 | The operator reads the operator guide. | Document: running the helper on a desktop, completing verification, copying the printed line, pasting it into **Settings › LeBonCoin session**, checking the result with existing refresh controls and the settings hint, renewing when the hint reports a rejection, and clearing by saving an empty field. | FR-LBC-CAP-014 | Valid capture starts on a desktop with a graphical display (user decision 7). | Reliably open a visible browser window showing the requested listing or LeBoncoin's verification page, isolated from the operator's personal profile. | On the supported desktop (including a GNOME Wayland session with Google Chrome installed), a new browser window appears on screen within a bounded startup time and displays LeBoncoin. Repeated runs open a window each time. If no window can be opened, the helper fails per FR-LBC-CAP-017 instead of silently waiting or exiting. |
| FR-LBC-CAP-015 | The helper runs. | Show progress messages in the terminal as each stage begins, starting immediately after launch: checking prerequisites/input, opening the browser (naming the browser used), waiting for the operator to complete verification (with instructions and the deadline), checking the listing, and success. | A message appears within about one second of starting, before any slow step; each later stage produces its message when it begins, not only when the helper exits. ## States and corner cases (revision 2)

- Stages: validating input and prerequisites, opening the browser, waiting for human verification, checking the listing, printed success, or failed. Each is visible in the terminal (FR-LBC-CAP-015).
- The helper's own controls (Ctrl+C) are keyboard usable; accessibility of LeBoncoin's challenge is outside the application's control.
- A listing that is removed or cannot be verified does not produce a value; the operator can retry with another active listing.
- Printing the value does not add an item, collect a price, or prove server acceptance; the operator saves it in Settings and checks with existing controls.
- Terminal scrollback and copy/paste buffers will contain the value; this is accepted by user decision 6 and documented as a secret-handling caution (FR-LBC-CAP-013).
- Reported defect context (2026-10-03, coordinator observation on a GNOME/Wayland host with system Node.js 20.19.2 and Google Chrome 149): Chrome processes started but the helper reported “Browser closed before a verified listing was captured.” and exited early; with a missing output directory it failed before launch with a generic message. FR-LBC-CAP-014 to FR-LBC-CAP-018 define the expected observable behavior; root-cause analysis is technical work.
