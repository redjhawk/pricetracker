# Technical spec: describe runConcurrently instead of t.Parallel

Status: todo
Source: PR #306, R1-04

**Problem:** `doc/specifications/http-server-timeouts/technical.md:135` says each long subtest of `TestHTTPServerLimits_Live` calls `t.Parallel()`. The test uses `runConcurrently` (`internal/httpapi/http_server_limits_test.go:142-154`), which calls `t.Run` from goroutines so that the GOMAXPROCS limit of `t.Parallel` does not queue the long waits.

**Suggested work:** Change the sentence to describe `runConcurrently` and why it is used.
