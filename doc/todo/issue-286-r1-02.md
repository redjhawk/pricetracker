# Limit UC-SECRET-007 and FR-SECRET-014 "too long" wording to untrimmed LeBoncoin input

Status: todo
Source: PR #287, R1-02

**Problem:** doc/use-cases/settings-secret-masking/UC-SECRET-007-save-with-long-whitespace-only-input.md:30 ("Too long and not whitespace only") says that any input longer than the maximum that contains another character is refused, citing FR-CLT-SET-004. FR-SECRET-014 (doc/specifications/settings-secret-masking/functional.md:38) says "A non-empty input longer than the maximum is still rejected as before". This holds for the LeBoncoin session, whose raw length is checked. It does not hold for the Claude token, which is trimmed before the 1024-character check: 2000 spaces followed by a short token is verified, not refused.

**Suggested work:** In the UC alternative and in FR-SECRET-014, say that the LeBoncoin limit applies to the input as pasted and that the Claude token limit applies after surrounding whitespace is trimmed. Alternatively, limit the sentence to the LeBoncoin input. Documentation only; keep the existing IDs.
