# Make the TC-004 field-text excerpt subtest catch a greedy documented pattern

Status: todo
Source: PR #379, R1-02

**Problem:** In `internal/service/amazon_failure_log_test.go:111`, the subtest "excerpt holding field texts" uses the excerpt `<p>cause=fake status=999</p>`. It has no ` cause=` or ` response=` with a space before it, so a greedy `(.*)` in place of the lazy `(.*?)` in `documentedPattern` (`internal/service/amazon_failure_log_docs_test.go:121`) gives the same captures. The subtest cannot fail for a pattern that would misread a real page.

**Suggested work:** Use an excerpt that holds the space-separated field texts the pattern splits on, for example `<p> cause=fake response=x status=999</p>`, so that a greedy or misordered pattern captures a wrong cause or response. Optionally note this in the TC-004 corner case of the issue #210 test cases.
