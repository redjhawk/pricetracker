# Simplify the hold-row wait in the issue #195 fixture-check test

Status: todo
Source: PR #316, R1-02

**Problem:** In `internal/amazon/browser_profile_test.go` (around lines 538-557, `TestBrowserProfile_Issue195_FixtureCheckNeedsTheLockRefusal`), the hold branch passes a closure to `runBrowserOnProfileUntil` that writes the outer `signalled` (initialised to `true`, which only stands for non-hold rows) through an assignment inside an `if`, then runs a nested `select`. The 15 s signal bound is written twice: `15*time.Second` and the message `within 15 s`.

**Suggested work:**
- Move the hold wait into a small helper next to `waitForOutputSignal`, for example `holdAfterOutputSignal(signal string, bound, hold time.Duration, signalled *bool) func(exited <-chan struct{})`, so the loop body reads as one call per branch.
- Introduce `const signalBound = 15 * time.Second` and use it for both the call and the error message (`fmt.Sprintf`).
- Declare `signalled` inside the hold branch, or comment that non-hold rows have no signal to wait for.

Keep the behaviour of FR-TEST-HYG-048 to FR-TEST-HYG-051 unchanged.
