# Reload the item details after a refused AI review request

Status: todo
Source: PR #368, R2-01

**Problem:** If the details page is stale (the Amazon item was stopped or lost its current price after the page loaded, e.g. by a scheduled check), **Refresh AI review** gets `409 AI_REVIEW_ITEM_STOPPED` or `AI_REVIEW_NO_CURRENT_PRICE`. `handleAiReviewRefresh` in `src/App.tsx:275-287` reloads the item only on success, so the button stays visible and enabled and the stopped / no-current-price notice of FR-AMZ-ITEM-AIR-032/033 is not shown until the user navigates away.

**Suggested work:** After a failed request, also reload the details (for example `getItem(id).then(setDetailItem).catch(() => {})` in the catch), so `unavailableReason` hides the button and shows the matching notice in `src/components/AmazonAiReview.tsx`. This works for both platforms. Add an e2e case where the mock answers the POST with `409 AI_REVIEW_ITEM_STOPPED` and the next GET returns `unavailableReason: "stopped"`.
