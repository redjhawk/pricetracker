# Add regression tests for keeping the browser's last stderr line in the failure cause

Status: todo
Source: PR #206, R3-01

**Problem:** `lastBytes` and `exitReasonBytes` (`internal/amazon/cdp.go:113-134`) keep the newest stderr line of a browser that cannot start (FR-AMZ-BRET-005), but no test checks this. The TC-006 subtest 'browser writing several lines' (`internal/amazon/browser_retrieval_test.go:604-615`) only checks that `stub line` appears, so it would also pass if the end were cut again by a later change to `exitReasonBytes` or `logText` (`internal/amazon/browser.go`).

**Suggested work:** In a new test file (for example `internal/amazon/cdp_exit_reason_test.go`):
1. Unit test `lastBytes`: short text comes back unchanged; long text keeps its last line; the result is at most `limit` bytes, starts with `…`, and is valid UTF-8 when the cut falls inside a multi-byte rune.
2. A stub-browser run like the TC-006 one that writes 40 long stderr lines and requires `stub line 40` (the last line) in `FailureCause`.
