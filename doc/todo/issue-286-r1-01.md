# Say that the Claude token 1024-character limit applies to the trimmed value

Status: todo
Source: PR #287, R1-01

**Problem:** API_SPECIFICATION.md:365 ("Save settings", `claudeToken.value`) says "the 1024-character limit applies only to a value that is not whitespace only". A reader can take this to mean the raw length is checked, as for the LeBoncoin session (8192 on the raw input). The server actually trims first and checks the trimmed token (`tokenChangeFor` and `validateClaudeToken`, internal/service/settings.go:99-113), so `"<2000 spaces>sk-ant-..."` is accepted and verified.

**Suggested work:** Reword it as "the 1024-character limit applies to the trimmed value, so surrounding whitespace, and a whitespace-only value of any length, never makes it too long". Make the matching sentence in doc/specifications/settings-secret-masking/technical.md:256 ("the 8192 / 1024-character limits apply only to input that is not whitespace only") say the same thing. Documentation only.
