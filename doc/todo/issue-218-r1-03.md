# Assert that a failed capture setup leaves log and stdout unchanged

Status: todo
Source: PR #391, R1-03

**Problem:** `StartCapture` (`internal/amazon/amazontest/capture.go:28`) creates the pipe before redirecting the logger, so a failed setup leaves both destinations unchanged. That is one of the deliberate differences from `master` (`doc/specifications/test-suite-hygiene/technical.md`, issue #218 design). `TestCaptureOutput_Issue218_TC009_SetupFailureFailsTheTest` (`internal/amazon/amazontest/capture_test.go:446`) checks only the failure and the `too many open files` text. It would still pass if `os.Pipe()` moved back after `log.SetOutput`.

**Suggested work:** In the child branch, save `log.Writer()` and `os.Stdout` before `CaptureOutput(t)`. Register a `t.Cleanup` that prints a marker such as `destinations unchanged` when both still equal the saved values. Have the parent require that marker. Add the corner case to TC-009 in the test-suite-hygiene specifications.
