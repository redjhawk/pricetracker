# Clear the Amazon browser HTTP cache even when the check is cancelled

Status: todo
Source: PR #231, R2-01

**Problem:** In `internal/amazon/browser.go` (around line 448), `browserTab.load` sends `Network.clearBrowserCache` with the check's `ctx`. If that context ends (server shutdown, `amazonCheckTimeout`) while `awaitDocument` waits, `cdpBrowser.call` (`internal/amazon/cdp.go:174-216`) writes the request but returns `ctx.Err()` without waiting for the reply. `close` then sends `Browser.close` right away, so the browser may exit before the cache is cleared, and the body of an attachment response may stay in `<profile>/Default/Cache` (FR-AMZ-HCHK-014). The log line also reports `context canceled` even though the request was sent. Also, when `ctx` ends while `Page.navigate` is still running, `load` returns through `loadError` and never clears the cache.

**Suggested work:** Run the clear in its own bounded context that ignores cancellation, e.g. `clearContext, cancelClear := context.WithTimeout(context.WithoutCancel(ctx), 5*time.Second)`. Consider also clearing on the cancelled `Page.navigate` path before returning. Update the TS-AMZ-HCHK-017 bullet "The call uses the check's `ctx`" in `doc/specifications/amazon-human-checks/technical.md` (around line 358) to match.
