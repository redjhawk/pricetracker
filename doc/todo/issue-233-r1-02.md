# TC-004 'while requested': report whether the held download reached the browser

Status: todo
Source: PR #236, R1-02

**Problem:** In `internal/amazon/browser_interrupted_test.go` (around line 294), the 'while requested' subtests of `TestBrowserInterrupted_TC004_RealCheckInterruptedAroundADownloadWritesNoFile` write the download only at `interruptAt + 100 ms`. After the change the browser usually closes first, `waitUntil` returns false and nothing is written, so `AssertNoDownload` has nothing to find. Nothing shows whether the 'answer cached after the clear' risk of the tech spec was exercised.

**Suggested work:** Record when `writeDownload` completed and flushed (for example a `wroteAt` under `mu`). After the check, `t.Logf` whether the download reached the browser. Consider a variant that releases the answer before the clear (for example right at `interruptAt`), so a run that delivers the body after the interruption is reached at least sometimes. Do not weaken `AssertNoDownload`.
