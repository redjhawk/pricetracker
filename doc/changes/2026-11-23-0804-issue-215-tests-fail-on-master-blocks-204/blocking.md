# Blocking review comments (round 1)

## R1-01 `tests/leboncoin-session-settings.spec.ts:623`

Enter, ArrowDown, Enter with no wait has the same race this issue fixes for Escape. In @carbon/react 1.117, `OverflowMenu.handleKeyPress` (arrow keys) is attached only to the menu `ul`. Focus moves into the menu only after `FloatingMenu` places it (technical.md, 'Cause'). An ArrowDown pressed before that reaches the trigger and is lost. Focus then lands on the first entry, Information, and the final Enter opens the Information modal, not Settings. The `expect(... dialog 'Settings').toBeVisible()` then fails intermittently under full-suite load. This copies the existing 'header menu: …' test (lines 163-165, unchanged), which has the same weakness, so the issue's goal of a reliably green `npx playwright test` is not met. It also contradicts the new corner case in app-header-menu/functional.md: 'Keys pressed in quick succession give the same result as the same keys pressed slowly (FR-APP-MENU-007)'. Fix one of two ways. (a) In `AppMenu`, extend the trigger `onKeyDown` so ArrowDown/ArrowUp while open moves focus to the first/last entry and is not lost. Or (b) scope the functional bullet to Escape and, in both tests, wait for `menuitem 'Information'` to be focused before pressing ArrowDown, as TC-001 does at lines 501-502.

Triage: Confirmed in @carbon/react 1.117: arrow keys are handled only by the menu items and the `ul` (`OverflowMenu.js` line 278), and `FloatingMenu` focuses the first entry only in an effect after placement (`FloatingMenu.js` lines 150-156). So an ArrowDown pressed right after Enter reaches the trigger, which ignores it. The new TC-003 test (`tests/leboncoin-session-settings.spec.ts` lines 622-624) can then open Information instead of Settings, which is the same load-dependent race this issue is meant to remove. It also contradicts the new FR-APP-MENU-007 corner case, "keys pressed in quick succession give the same result as the same keys pressed slowly".
