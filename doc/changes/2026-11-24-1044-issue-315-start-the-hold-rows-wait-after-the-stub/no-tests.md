# No red phase for issue #315

The change is the test code itself: the hold stub and the hold rows' wait of `TestBrowserProfile_Issue195_FixtureCheckNeedsTheLockRefusal` in `internal/amazon/browser_profile_test.go`. That file is locked after this stage, and FR-TEST-HYG-052 allows no other file outside `doc/`, so the development stage cannot write any of it. This stage delivers the whole change, as the technical specification says (TS-TEST-HYG-067). A normal run passes before and after the change, so no test can fail first on a missing implementation. The red gate is skipped. The development stage writes no code: it only sets the statuses.

## Delivered in `internal/amazon/browser_profile_test.go`

- `runBrowserOnProfile` is now a wrapper, with the same signature and `select`, around the new `runBrowserOnProfileUntil(t, executable, profile, server, path, wait func(exited <-chan struct{}))`. That function has the old body, with the `select` replaced by `wait(exited)`. `assertBrowserRefusesProfile` and its 15 s call are not edited.
- `refusalStub` gains ``Signal string `json:"signal"` ``. `refusalStubBrowser` now returns `(executable, signal string)`. It puts the script and `output-written` in one `t.TempDir()` of the row, and sets `Signal` on its own copy of the stub, so the rows table and `row.stub` are unchanged.
- In `TestBrowserProfile_Issue195_RefusalStubProcess`, a `Hold` stub creates `stub.Signal` (empty, `0o600`) after its request and `Stderr` write, then sleeps one minute. When the variable is empty, the stub still returns at once.
- New `waitForOutputSignal(signal, exited, bound) bool`. It polls `os.Stat` every 10 ms, stops on the exit (after one last `Stat`) or at the bound, and reports whether the file exists.
- In the `t.Run` loop, a row with `row.stub.Hold` runs through `runBrowserOnProfileUntil`. It waits for the signal for 15 s, then for 2 s or the exit. Without a signal it reports `t.Errorf("the stub did not signal its output within 15 s")`, and the other assertions still run, including `ESRCH`. A non-hold row keeps `runBrowserOnProfile(…, 15*time.Second)`. The choice reads only `Hold`.
