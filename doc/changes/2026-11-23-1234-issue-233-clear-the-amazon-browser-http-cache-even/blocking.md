## R1-01 `internal/amazon/browser_interrupted_test.go:338`

TC-004 'after the download was offered' never checks that the check was still running when its context ended. The server flushes the attachment at interruptAt - 100 ms. Page.navigate then returns errorText. As soon as Chromium reports the 200 Document response (TS-AMZ-HCHK-017 expects it, possibly before the error), awaitDocument returns at once and load calls clearCache with a live context. Collect returns about 100 ms before `at`, so the deadline or cancel interrupts nothing. The subtest then passes against the pre-change code as well (the old inline clear used a live ctx) and does not prove FR-AMZ-HCHK-015. The technical spec's risk note requires a missed interruption point to fail with a message, never to pass silently; the arrival and flush checks do not catch this case. Fix: record when Collect returns and fail with 'interruption point missed' if it returned before `at`, or check that the failure cause is the interruption. If real Chromium can never reach this point, say so in the test and the spec and rely on TC-001 for it, rather than keeping a subtest that passes without exercising it.
